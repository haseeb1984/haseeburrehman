CASE 01 / INDEPENDENT ENGINEERING PROJECT

PulseDrift — schema-drift resilience platform

API consumers can break when upstream payloads evolve without notice. Retries alone do not fix incompatible contracts; they can simply repeat the same failure. PulseDrift explores a controlled recovery layer between upstream APIs and dependent services.

CONCEPTUAL CONTRACT RECOVERY FLOW01 / PULSEDRIFT
UPSTREAM APICHANGING PAYLOAD
→
DRIFT DETECTIONCOMPARE CONTRACT
→
REPAIR VALIDATIONBOUNDED CANDIDATE
→
DOWNSTREAM SERVICERECOVERED FLOW
IDEMPOTENCY CACHESAFE REQUEST REPLAY
↔
DEAD-LETTER QUEUEEVENT REPLAY

Engineering focus

  • Detect schema and payload drift in real time.
  • Validate repair candidates before applying bounded changes.
  • Cache idempotent requests to avoid unsafe duplicate processing.
  • Support DLQ event replay for controlled recovery.

Scope & status

Independent engineering project with a companion mock environment. The portfolio describes intended system capabilities and architecture focus; it does not claim measured production uptime improvements or customer deployments.

Stack references include FastAPI, Python, MongoDB and React.

CASE 02 / ENTERPRISE INTEGRATION

Attendance & biometric integration engine

The problem was not simply collecting a clock-in event. Device-level attendance needed to be reconciled with HR policies, rosters, leave, work-from-home cases and reporting across regions.

Responsibilities

Designed a multi-region .NET/PHP integration platform using REST API middleware between Hikvision/eSSL devices and Zoho People. Scope included attendance, rosters, leave, work-from-home scenarios, salary deduction logic and regional workforce reports.

Reported operational outcome

Automated regional daily logs and executive summaries reduced manual tracking overhead by 40%, saving more than 15 reporting hours per week, according to the project record.
